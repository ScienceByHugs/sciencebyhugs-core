# Core Security Hardening V1

Applied to the production Supabase project on 2026-09-24.

## Database access

- Revoked PUBLIC, anon, and authenticated EXECUTE on `sync_referral_rewards_for_customer(uuid)`.
- Revoked PUBLIC, anon, and authenticated EXECUTE on `handle_referral_reward_sync()`.
- Kept EXECUTE for `service_role`, which is used by the protected referral Edge Functions.
- Verified `referral-dashboard` and `customer-rewards` call reward sync with the service-role client.
- Added explicit deny policies and removed direct anon/auth table grants for `catalog_sync_runs`, `message_templates`, and `core_audit_events`.

## Database performance/security

- Added covering indexes for the five foreign keys flagged by Supabase advisors.
- Updated `customer_rewards_select_own` to evaluate `auth.uid()` through a select init-plan.
- Verified the service-role referral reward function executes successfully in a rolled-back transaction.
- Security advisors now report only the hosted Auth leaked-password-protection setting.
- Performance advisors no longer report unindexed foreign keys or auth RLS init-plan warnings.

## Repository supply chain

- Pinned frontend dependency versions.
- Committed `package-lock.json` generated by GitHub Actions from the exact dependency pins.
- Core CI now installs exclusively with `npm ci` and npm cache support.

## Hosted Auth setting still required

Supabase leaked-password protection remains disabled. The connected Supabase management tools do not expose a mutation for this Auth setting, so it must be enabled in the hosted Supabase Auth password-security settings. This is the only remaining security advisor warning after the database changes above.
